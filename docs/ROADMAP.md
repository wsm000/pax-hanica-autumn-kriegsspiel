# Roadmap

This roadmap is intentionally staged around playable proof rather than content volume.

## 0. Design Foundation

- [x] Create the public repository skeleton.
- [x] Record the player role, unit scale, and initial time model.
- [ ] Define the first faction pair and one introductory scenario.
- [ ] Write a small rules glossary.
- [ ] Decide the initial technology stack.

## 1. Core Simulation Prototype

- [ ] Represent a map, terrain, and positions.
- [ ] Represent units of roughly one hundred people.
- [ ] Implement persistent orders with duration and stop conditions.
- [ ] Advance standard six-hour turns.
- [ ] Resolve basic movement, detection, combat, morale, and supply.
- [ ] Produce a readable event and report log.
- [ ] Make simulation results reproducible with a seed.

## 2. First Vertical Slice

- [ ] Build one compact scenario with two factions.
- [ ] Add a clear objective and an operational deadline.
- [ ] Add limited reconnaissance, support, and a reserve.
- [ ] Add a local two-hour combat phase.
- [ ] Add a result screen and post-scenario review.
- [ ] Complete one full scenario from deployment to resolution.

## 3. Playtest and Revision

- [ ] Run internal playtests using the template in `PLAYTEST.md`.
- [ ] Identify decisions that are dominant, meaningless, or opaque.
- [ ] Adjust information quality, friction, and pacing.
- [ ] Test whether a two-day scenario fits within 20–40 minutes.
- [ ] Publish a first playable development build.

## 4. Expansion

Only after the vertical slice is enjoyable:

- [ ] Expand the fictional setting through additional scenarios.
- [ ] Add faction doctrines and asymmetric capabilities.
- [ ] Add campaign persistence if it improves decisions.
- [ ] Improve AI, tools, accessibility, and presentation based on playtest evidence.
